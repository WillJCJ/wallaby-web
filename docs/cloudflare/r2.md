# R2

Festival photos and videos are stored in a Cloudflare R2 bucket and served through the Worker.

The site does not link directly to R2 public URLs. Media requests go through Worker routes:

- `GET /api/photos/:key` for images
- `GET /api/videos/:key` for videos

Both routes read from the `PHOTOS_BUCKET` binding and return the matching object with the correct response headers.

## Create the bucket

Create the shared bucket used by local, preview, and production environments:

```bash
wrangler r2 bucket create wallaby-web
```

If you want separate buckets per environment, create those buckets first and update `wrangler.jsonc` to match.

## Configure the Worker binding

Worker code expects this binding name:

```toml
[[r2_buckets]]
binding = "PHOTOS_BUCKET"
bucket_name = "wallaby-web"
```

The same binding must exist under each Wrangler environment that serves photos.

## Local development

Photos and videos are not bundled with the repository. Run the following command to pull
them into the local Wrangler R2 state so they load during `npm run dev:wrangler`:

```bash
npm run r2:sync-local
```

## Upload media

Photo ids in [site/_data/photos.json](../../site/_data/photos.json) must match the object keys stored in R2.

Example uploads:

```bash
wrangler r2 object put wallaby-web/2022-campfire-bois.jpg --file /path/to/2022-campfire-bois.jpg
wrangler r2 object put wallaby-web/2023-dance-floor.jpg --file /path/to/2023-dance-floor.jpg
wrangler r2 object put wallaby-web/videos/late-night-singalong.mp4 --file /path/to/late-night-singalong.mp4
```

Keep the original file extension in the object key. The Worker falls back to the content
type inferred from the extension if object metadata does not include one.

## How the site reads media

The photos page stores metadata in [site/_data/photos.json](../../site/_data/photos.json).

Image entries should use:

- `id`: the exact R2 object key, for example `2022-campfire-bois.jpg`
- `alt`: descriptive alt text, for example `2022 - Campfire bois`
- `caption`: the short visible caption used in the gallery

Template and client code request each image from:

```text
/api/photos/<id>
```

Video entries use the same metadata file. Their `id` should match the filename stored
under the `videos/` prefix in R2, for example `late-night-singalong.mp4`.

Template and client code request each video from:

```text
/api/videos/<id>
```

This keeps the bucket behind the Worker and avoids hard-coding public R2 URLs in the front end.

## Troubleshooting

- `503 Photos bucket is not configured`: the `PHOTOS_BUCKET` binding is missing from the active Wrangler environment.
- `404 Photo not found`: the filename in
  [site/_data/photos.json](../../site/_data/photos.json) does not match an object key in R2.
- `404 Video not found`: the filename in
  [site/_data/photos.json](../../site/_data/photos.json) does not match an object key
  under the `videos/` prefix in R2.
- Wrong image type in the browser: re-upload the object with the correct extension or content type metadata.
